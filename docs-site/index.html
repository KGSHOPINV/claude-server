Server Kit

A one-command bootstrap that turns a bare Ubuntu server into a fully running self-hosted stack — with a browser-based control panel, push alerts, automated backups, and 16 pre-configured services.

Get Started → Port Reference

Two Repos, One System

The project is split across two GitHub repositories with a clear division of responsibility:

INSTALLER

server-kit
  • 16 numbered setup scripts
  • Docker compose files for every service
  • CLI tools deployed to /usr/local/bin/
  • One-command install.sh
  • Clones the Hub at install time

CONTROL PANEL

claude-server
  • hub/server.py — Python API server
  • hub/app.html — browser control panel
  • hub/mobile.html — mobile view
  • Vault, terminal, survey, runbooks
  • Updates independently of Docker stack

Key design principle: The Hub and the Docker stack update independently. Push new Hub features without touching containers. Restart containers without reloading the UI.

Installation

One command. Four questions. Everything else is automated.

Prerequisites

  • Ubuntu 24.04 LTS (fresh install) — other Debian-based distros work, see OS modes below
  • SSH access with sudo privileges
  • At least 20 GB disk, 4 GB RAM (more is better)
  • Internet access from the server

Quick Install

git clone https://github.com/KGSHOPINV/server-kit ~/server-kit
cd ~/server-kit
bash install.sh

The Four Questions

  1. Server IP

    The LAN IP of this machine — e.g. 192.168.1.229. Used to configure services and firewall rules.

  2. SSH Username

    The user running the hub service — e.g. admin1. The hub runs as this user via systemd.

  3. Timezone

    e.g. America/Los_Angeles. Sets system time, alert schedules, and log timestamps.

  4. Admin Password

    Your hub web login password. Stored as SHA-256 in SQLite — never written to any file.

OS Modes

The installer detects your OS at startup and uses the correct package manager throughout — no hardcoded apt calls:

# Detected automatically — you don't set this
Ubuntu / Debian  →  apt install -y
CentOS / RHEL    →  dnf install -y
Fedora           →  dnf install -y
Arch Linux       →  pacman -S --noconfirm

Tested on Ubuntu 24.04 LTS. Other distros are supported in theory but package names may differ. The installer will warn you if it can't identify your OS and ask before continuing.

What Happens Next

The installer runs 16 numbered scripts in order. Each one logs what it's doing. The whole process takes 5–15 minutes depending on your internet connection.

When it's done:

# Browse to your hub
http://YOUR_SERVER_IP:8765

# Login with
Username: admin
Password: (whatever you set in question 4)

A browser-based control panel that lives at http://SERVER_IP:8765. It gives you a visual interface over SSH — everything you'd do on the command line, available from any browser.

Home Dashboard

The pinned Home tab shows live server state on load — disk %, RAM, load average, container count, and a per-service status grid. Data comes from the hub's /api/status and /api/services endpoints, refreshed every 60 seconds.

Survey

A one-click deep health check. Runs 6 parallel SSH commands and surfaces: all container states with ages, per-filesystem disk usage, RAM, CPU load, maintenance log tail, and coloured alerts for anything over threshold.

Vault

Client-side AES-256-GCM password manager. The master password is derived with 200k rounds of PBKDF2 — it is never sent to the server. The encrypted blob is stored in SQLite. If you forget the master password, the vault cannot be recovered.

Alerting

Three layers of push notifications to your phone — state-change alerts, a daily brief, and scheduled disk monitoring.

ntfy Setup

ntfy runs on :8085. Subscribe from your phone:

  1. Install the ntfy app (Android/iOS)
  2. Add server: http://SERVER_IP:8085
  3. Subscribe to topic: server-alerts

Make sure port 8085 is open in UFW if you're accessing from a phone on your LAN: sudo ufw allow 8085/tcp

Alert Layers

Runbooks

Step-by-step response guides for the most common server problems. Available in the hub under Ops → Runbooks.

SSH Lockout (Fail2Ban)

sudo fail2ban-client set sshd unbanip YOUR_IP

Check your work PC's IP first: usually 192.168.1.192 on the local network.

Container Won't Start

dklogs CONTAINER_NAME          # 1. Check logs for error
dkrestart CONTAINER_NAME       # 2. Try restart
cd /srv/docker/NAME && docker compose down && docker compose up -d  # 3. Full restart

Disk Almost Full

df -h                          # 1. Find what's full
docker system prune -f         # 2. Remove unused images/volumes
docker system df               # 3. Check Docker disk usage

Hub Won't Load

systemctl --user status hub    # 1. Check status
systemctl --user restart hub   # 2. Restart
journalctl --user -u hub -f    # 3. Watch logs
sudo ufw status                # 4. Check firewall

Portainer Locked Out

cd /srv/docker/portainer
docker compose down
docker volume rm portainer_data
docker compose up -d
# Browse to :9443 and set up a new admin account

Full Health Check

health-check    # Run from SSH — full status report

Updating

Update the Hub (App Only)

cd ~/hub && git pull origin master
systemctl --user restart hub

Or from inside the Hub: Settings → Security → Hub Update → Pull Latest & Restart

Update Docker Containers

server-update   # Updates all containers + system packages

Or per-service:

cd /srv/docker/SERVICE
docker compose pull
docker compose up -d

Update server-kit Scripts

cd ~/server-kit && git pull
# Re-run any individual script if needed:
bash 10-linux-helpers.sh

The hub and Docker stack update independently — you can push new hub features any time without touching your running containers.

Troubleshooting

Service Unreachable on Expected Port

  1. Is the container running? dkps | grep NAME
  2. Is the port open in UFW? sudo ufw status | grep PORT
  3. Is anything listening? sudo ss -tlnp | grep PORT
  4. Check container logs: dklogs NAME

Hub Shows Offline / Won't Connect

systemctl --user is-active hub     # Should say: active
curl http://localhost:8765/api/status  # Should return JSON

SSH Times Out

If SSH keeps dropping, add these to your ~/.ssh/config on the connecting machine:

Host 192.168.1.229
  ServerAliveInterval 30
  ServerAliveCountMax 3
  ConnectTimeout 20

Docker Compose Not Found

docker compose version   # Should work — plugin style
docker-compose version   # Old standalone — may not be installed

If docker compose fails, Docker wasn't installed via the official script. Re-run script 02.

Reset Hub Password

python3 -c "
import sqlite3, hashlib
pw = 'YOUR_NEW_PASSWORD'
h = hashlib.sha256(pw.encode()).hexdigest()
c = sqlite3.connect('/home/admin1/db/server.db')
c.execute('UPDATE users SET password_hash=? WHERE username=?', (h, 'admin'))
c.commit()
print('Done')
"
