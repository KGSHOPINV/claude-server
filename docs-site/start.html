Step 1 of 4

Before you start

Run through this checklist. The installer handles everything else — these are the only things you bring to the table.

  • A machine to be the serverPhysical PC, old laptop, mini-PC, or a VM — anything with 4 GB RAM and 40 GB disk. More is always better.
  • Linux installed and bootedUbuntu 24.04 LTS is the tested default. Debian, Fedora, and Arch also work — see the OS tabs below.
  • SSH access from your main computerYou'll need to connect over the network. Run ssh user@SERVER_IP and make sure it works before continuing.
  • Internet on the serverThe installer pulls packages and Docker images. A wired connection is best for the initial setup.
  • The server's local IP addressRun ip a on the server and note the IP — e.g. 192.168.1.100. You'll enter this during the install.

Pick your OS

The installer detects this automatically — but make sure you know which package manager your system uses.

✓ Fully tested. Ubuntu 24.04 LTS is the primary target — all scripts are written and validated against this.

# Confirm Ubuntu version
lsb_release -a
# Should show: Ubuntu 24.04 LTS

Package manager: apt · Installer variable: PKG_INSTALL="apt install -y"

✓ Supported. Debian 11+ (Bullseye and later). Nearly identical to Ubuntu — same apt package names.

# Confirm Debian version
cat /etc/debian_version
# Should be 11 or higher

Package manager: apt · Installer variable: PKG_INSTALL="apt install -y"

⚠ Community supported. Fedora 38+ and RHEL/Rocky/Alma 9+. Most packages install fine — a few names differ from the Ubuntu equivalents.

# Confirm Fedora/RHEL
cat /etc/os-release | grep NAME
# Enable EPEL if on RHEL/Rocky:
sudo dnf install -y epel-release

Package manager: dnf · Installer variable: PKG_INSTALL="dnf install -y"

⚠ Advanced users. Arch Linux (and Manjaro) work but require some manual intervention. Package names and service management differ.

# Update package database first
sudo pacman -Syu
# Confirm system is up to date before installing

Package manager: pacman · Installer variable: PKG_INSTALL="pacman -S --noconfirm"

Not sure what you have? Run cat /etc/os-release on the server — the NAME field tells you everything.

Step 2 of 4

Connect & download

SSH into your server and pull the kit down. Two commands. Takes about 30 seconds.

Open an SSH connection

From your main computer's terminal — replace YOUR_USER and SERVER_IP with your actual values:

ssh YOUR_USER@SERVER_IP

First time connecting? You'll see a fingerprint prompt — type yes and press Enter. This only happens once per machine.

Clone server-kit

Once you're in, run this on the server:

git clone https://github.com/KGSHOPINV/server-kit ~/server-kit

Enter the directory

cd ~/server-kit

No git on the server yet? Install it first: sudo apt install -y git (Ubuntu/Debian) or sudo dnf install -y git (Fedora).

Step 3 of 4

Run the installer

One command. It asks you four questions, then runs 16 setup scripts in order. Go get a coffee — it takes about 10 minutes.

The command

bash install.sh

The four questions — click each to see what to enter

1
Server IP address
▶

Your server's local LAN IP — the one you SSH'd into in Step 2. Example: 192.168.1.229

This is used to configure UFW firewall rules, Docker bind addresses, and service URLs baked into the hub. Get it right — it's used everywhere.

2
SSH username
▶

The Linux username you logged in as. Example: admin1 or ubuntu

The hub runs as a systemd service under this user. This is also the user that gets the bash aliases, CLI tools, and hub folder in their home directory.

3
Timezone
▶

Your timezone in tz format. Examples: America/Los_Angeles · America/New_York · Europe/London · Australia/Sydney

Sets the system clock, alert schedules (like the 7am daily brief), log timestamps, and backup windows. Not sure of the exact format? Run timedatectl list-timezones | grep America to search.

4
Hub admin password
▶

The password you'll use to log into the hub web UI at :8765. The username will be admin.

It's stored as a SHA-256 hash in SQLite — never written to any file in plaintext. You can reset it later if you forget it.

What happens next

OS detectionReads /etc/os-release and sets the right package manager for your distro
Scripts 01–16 run in orderEach one logs what it's doing. Most take 30–90 seconds. Docker images are the longest part.
Hub is clonedserver-kit clones the claude-server repo to ~/hub on your behalf
hub.service startssystemd starts the Python API server and keeps it running. It restarts automatically if it crashes.
DoneYou'll see a summary of what's running and the URL to open. Total time: ~10 minutes on a good connection.

Script 16 (AI stack) asks if you want it enabled. Unless you have a GPU, say no — Ollama runs on CPU only and will peg your cores at 100% whenever it's active.

Step 4 of 4

First login

Open a browser on any machine on your network. Type this in the address bar:

http://YOUR_SERVER_IP:8765

Login with username admin and the password you set in question 4. That's it — you're in.

First three things to do

📊 Check the dashboard Home tab shows live disk, RAM, load, and all service dots. Anything red needs attention.
🔔 Set up ntfy alerts Install the ntfy app, add your server at :8085, subscribe to server-alerts.
🐳 Open Portainer Services → Portainer (:9443) to see every container at a glance. Create your admin account before the timeout.

Add optional services

Script 08 has extras you can add any time — n8n, Redis, Adminer, Mailpit, Wiki.js and more. Re-run it from your SSH session:

cd ~/server-kit && bash 08-extras-setup.sh

You're done. From here, the full reference docs cover every service, port, CLI tool, runbook, and setting in detail.
