2 · How It All Fits Together

Everything runs as Docker containers managed by Portainer. Traffic from the internet (or local network) hits Nginx Proxy Manager (NPM) first, which routes requests to the correct container by domain or subdomain. Monitoring watches all containers; if something dies, Uptime Kuma sends an alert via ntfy.

Internet / LAN
      │
      ▼
Nginx Proxy Manager (port 81 admin, 80/443 traffic)
      │
      ├── Homepage   (port 3000)  ← dashboard overview
      ├── Portainer  (port 9443)  ← container management
      ├── n8n        (port 5678)  ← automation workflows
      ├── Supabase   (port 8000)  ← database platform
      ├── MinIO      (port 9001)  ← object storage
      └── [any other service]

Monitoring stack runs alongside everything:
  Uptime Kuma → watches all service URLs → alerts via ntfy
  Netdata     → real-time CPU/RAM/disk graphs
  Dozzle      → live container log viewer

Hub (port 8765) → browser-based control panel
  └─ Runs as systemd user service (hub.service)
  └─ Handles: terminal, service status, vault, TOTP gate

TOTP Gate Setup

  1. Open the hub → Settings → Security Gate
  2. Click "Set up TOTP" — scan the QR code with Google Authenticator / Authy
  3. Enter the 6-digit code to confirm setup
  4. All Terminal and shell commands now require TOTP verification
  5. Session lasts 30 minutes after unlock

10 · Maintenance & Backups

Nightly Maintenance Agent

A Python script (~/hub/maintenance.py) runs every night via systemd timer. It checks:

  • All container statuses — alerts if any are stopped
  • Disk usage — alerts if any partition is over 85%
  • TLS certificate expiry — alerts if <14 days remaining
  • System uptime and RAM

Alerts go to ntfy. Check timer status: systemctl --user status hub-maintenance.timer

Watchtower — Auto Updates

Watchtower runs every night at 4am and pulls new container image versions. Settings:

Image: containrrr/watchtower:1.7.1   # pinned — do not use :latest
WATCHTOWER_CLEANUP=true              # removes old images after update
WATCHTOWER_SCHEDULE=0 0 4 * * *     # 4am daily
DOCKER_API_VERSION=1.41             # required for Docker 29.x

Manual Backup

server-backup
# or
sudo server-backup
tail -50 /var/log/server-backup.log   # check result

Verify Everything After Changes

bash ~/server-kit/verify-install.sh

First Response Checklist

  1. Run health-check — gives a full status in one shot
  2. Check docker ps — are all expected containers up?
  3. Check journalctl --user -u hub -f — hub errors
  4. Check df -h / — disk not full?
  5. Check free -h — memory not exhausted?
  6. Reboot as last resort: sudo reboot

Hub DB Path

Hub resolves its SQLite DB to ~/db/server.db. If the ~/db/ directory is missing, all config reads/writes silently fail. Fix:

mkdir -p ~/db && cp ~/hub/db/server.db ~/db/server.db

Update Everything

# Pull new container images
cd /srv/docker && for d in */; do (cd "$d" && docker compose pull 2>&1 | tail -3); done

# Restart with new images

TOTP Setup

Hub supports 2FA for shell access via TOTP (RFC 6238 — compatible with Google Authenticator, Authy, 1Password). Set up via Hub → Settings → Security Gate. Secret is stored in ~/db/server.db (gitignored).
