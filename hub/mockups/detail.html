fksinv is not a project this server knows, so it cannot be recorded as having read bulletin 10

This is the live state of fks-services today. projects is empty, so every ack on that box is refused here — and GET /api/bulletin/10?project=fksinv answers 404 for the same reason, because a code is never handed out that the ack would then reject.

A reader that was never a project cannot be a true row in any matrix. The fix: POST /api/registry/fksinv first.

403 · not addressed to you

bulletin 11 is addressed to babyhelp, not fksinv

Scope is all or one project name. Reading someone else's scoped bulletin gets the same 404 as a bulletin that does not exist: bulletin 11 has no copy addressed to fksinv.

The two are answered identically on purpose — separating them would let a caller enumerate which projects a scoped bulletin went to.

403 · code does not match

pin does not match bulletin 10 for fksinv — read your copy again

Refused, not recorded: a recorded wrong pin is a lie in the matrix. Refused, not locked: re-reading is the correct response to getting it wrong, and locking would punish the only useful reaction.

It does not say what the right code was, and it does not distinguish "wrong code" from "somebody else's code". Both are answered by reading your own copy.

reread: GET /api/bulletin/10?project=fksinv

400 · incomplete

answer required — "none" is valid, silence is not

A 400 rather than a 403: a project retrying in a loop has to be able to tell "I sent the wrong thing" from "this is not mine to acknowledge".

And on the read side, before any of this: name yourself: ?project=<you> — because the confirmation code is per recipient, so there is no copy of any bulletin that is not addressed to somebody.
